# AGENTS.md

## Scope and intent
- This repository is currently a minimal Ent + Postgres bootstrap, not yet a full REST API.
- Runtime entrypoint is `main.go`; data model source of truth is `ent/schema/`.

## Big-picture architecture
- `main.go` prints a startup header, opens an Ent client, runs schema auto-create, then exits.
- `connectToDatabase()` in `main.go` builds a Postgres DSN and calls `ent.Open("postgres", dsn)`.
- On startup, `client.Schema.Create(context.Background())` applies schema resources automatically.
- Domain model is schema-first: `ent/schema/person.go` defines fields; Ent-generated files under `ent/` implement queries/mutations.

## Editable vs generated code
- Treat most files under `ent/` as generated and non-editable (`// Code generated by ent, DO NOT EDIT.`).
- Edit schema definitions in `ent/schema/*.go` (for example `ent/schema/person.go`), then regenerate Ent code.
- `ent/generate.go` contains the `go:generate` directive used to regenerate code.

## Core developer workflows
- Install/update deps: `go mod tidy`
- Build binary: `go install .`
- Run app directly: `go run .`
- Run installed binary helper: `./run.sh` (expects `$GOPATH/bin/smartgorest`)
- Sanity test command currently valid in this repo: `go test ./...` (packages report `[no test files]`).

## Ent schema workflow (project convention)
- Add entity skeleton: `go run -mod=mod entgo.io/ent/cmd/ent new <EntityName>`
- Regenerate Ent code after schema changes:
  `go run -mod=mod entgo.io/ent/cmd/ent generate ./ent/schema --feature sql/lock`
- Commit both schema changes (`ent/schema/*`) and regenerated artifacts (`ent/*.go`, `ent/<entity>/*`).

## Integration points and dependencies
- Database: PostgreSQL via `github.com/lib/pq` and Ent dialect `postgres` (`go.mod`, `main.go`).
- ORM/Codegen: `entgo.io/ent` (schema in `ent/schema`, generated client in `ent/client.go`).
- Connection details are currently hardcoded in `main.go`; `.env` exists but is not wired into runtime config.

## Project-specific guidance for AI agents
- Prefer changes in `main.go` + `ent/schema/*`; avoid manual edits in generated Ent files unless user explicitly asks.
- If changing fields/relations, always regenerate Ent code before finishing.
- Keep README commands aligned with actual repo state (for example, no `internal/` package exists today).
- When adding runtime behavior, preserve existing startup sequence: banner -> DB connect -> schema create.
